# Markdown 文档编写规范

本规范约定仓库内 Markdown 文档的结构、标题、表格、代码块与链接写法，适用于 `Docs/`、
`Meta/` 与仓库根下的所有 `.md` 文件。文件命名另见 [`FileNamingSpec.md`](FileNamingSpec.md)。

## 一、适用范围

| 文档类型 | 位置 | 命名 |
| --- | --- | --- |
| 开发规范 | `Docs/DevSpec/*Spec.md` | 大驼峰 + `Spec.md` |
| 接口说明 | `Docs/OpenAPI/<厂商>/<接口组>/<接口名>.md` | 与接口同名 |
| 目录索引 | 各目录 `README.md` | 固定 `README.md` |
| 仓库入口 | 根 `README.md` | 固定 `README.md` |

## 二、文件结构

- 一个文件只讲一个主题，主题写进一级标题；
- 一级标题（`#`）全文件只出现一次，位于第一行；
- 标题层级不跳级，不出现 `##` 之后直接 `####`；
- 章节顺序建议：概述 → 正文 → 示例 → 检查清单或相关链接；
- 文末如需列举相关文档，用「相关实现」「相关文档」小节，不在正文中途堆链接。

## 三、标题风格

两种风格，按文档类型选择，同一文件内不得混用：

| 文档类型 | 二级标题 | 三级标题 | 示例 |
| --- | --- | --- | --- |
| 规范类（`*Spec.md`） | 中文序号 | 与所属二级编号一致的数字小节 | `## 二、Go 代码` → `### 2.1 包目录` |
| 接口说明 | 语义标题，不编号 | 语义标题，不编号 | `## 请求参数` → `### 查询参数` |
| 目录索引 / README | 语义标题，不编号 | 语义标题，不编号 | `## 目录结构`、`## 包职责` |
| 章节较多的主题说明（如签名） | 可用中文序号 | 可不编号 | `## 三、计算步骤` |

要求：

- 标题简洁，能单独看懂，不写「其他」「补充」这类含糊标题；
- 编号与顺序一致，增删章节后同步重排，不允许出现跳号；
- 标题末尾不加标点。

## 四、正文

- 使用简体中文与中文标点；技术名词、代码标识符、专有名称保留原文；
- 代码、命令、文件名、字段名、请求头等一律用反引号包裹，与正文区分；
- 长段落按语义断行，每行控制在 100 个字符以内，便于 diff 与审阅；
  表格行、代码块与长链接不受此限，不为了凑宽度把参数行拆断；
- 并列项用 `-` 列表，有先后顺序的步骤用 `1.` `2.`；
- 不使用颜文字或装饰性符号，不写「显然」「众所周知」这类无法验证的表述；
- 结论要可验证：涉及状态、数量、路径时写明具体值，不写「大概」「可能需要」。

## 五、表格

- 必须有表头与分隔行；列数在整张表内保持一致；
- 单元格内不换行（Markdown 表格不支持），需要多项时拆列或用顿号列举；
- 一个单元格只表达一个值，不要把多类型、多状态挤进同一格；
  例如字段类型应拆成「字符串形式」「数值形式」两列，而不是写 `string | number`；
- 表格前用一句话说明表的用途，表格后不再重复表内内容。

## 六、代码块

- 代码块必须标注语言：`go`、`bash`、`json`、`yaml`、`text` 等；
- 命令块给出可直接复制执行的完整命令，不省略必要参数；
- 命令与其输出分开：输出用独立代码块或文字说明，不混在同一块里；
- 最小可运行示例优于大段伪代码；无法编译的示意代码要注明「示意，未验证」；
- 不粘贴真实凭据、令牌、密钥、内网地址与个人隐私数据。

## 七、链接

- 仓库内文档互相引用时使用相对路径，保证在 GitHub 上可点击跳转；
- 引用的文件必须真实存在，不引用未创建的文档；
- 外部链接使用完整 URL，不用短链；
- 链接文字说明目标内容，禁止使用「点击这里」「详情」这类无信息量的文字。

示例：从本文件引用规范与规格：

- `[HTTPAPIDocSpec.md](HTTPAPIDocSpec.md)`
- `[GetKLine.yaml](../../Meta/OpenAPI/MooMoo/QuoteAPIV2/GetKLine.yaml)`

## 八、强调与提示

- 强调用 `**粗体**`，全文使用克制，一段内不超过一处；
- 代码内容即使需要强调也保持原样，不用粗体改写代码；
- 不使用需要额外渲染器的语法（如 Mermaid 图、自定义容器），保证纯 Markdown 可读。

## 九、接口说明的固定结构

接口说明文档的小节顺序与字段表要求见
[`HTTPAPIDocSpec.md`](HTTPAPIDocSpec.md) 第 9.3 节，本规范不重复，只约束写法：

- 每个小节先给结论，再给表格或示例；
- 字段表用列区分类型与取值，精度、承载类型、是否可为 `null` 都写在表内；
- 接口表统一包含方法、站点、路径、`operationId`、代码入口与备注。

## 十、检查清单

- [ ] 一级标题唯一，无跳级标题
- [ ] 规范类文档使用中文序号，接口说明与 README 使用语义标题，未混用
- [ ] 表格列数一致，单元格内无换行、无多值堆叠
- [ ] 代码块都标注了语言，命令可直接执行
- [ ] 仓库内链接为相对路径且目标存在
- [ ] 没有凭据、内网地址等敏感内容
- [ ] 每行不超过 100 个字符（表格行、代码块与长链接除外），长段落已按语义断行
